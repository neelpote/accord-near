## Small implementation plan

Add one `near-contract-risk-analyst-v1` service on the existing provider/worker path. Reuse finalized single-block `operations.capture` and `incidents.changes`. The customer fixes the target account and expected initial code hash. Subsequent cycles compare against the preceding paid report from the same agreement, verified against its immutable receipt/hash. An initial report explicitly lacks a historical permission baseline.

Deterministic collection/normalization owns account identity, snapshots, code/key differences, observation timestamps and evidence IDs. The model receives only this bounded public evidence and can produce a structured explanation with references to those IDs. It has no wallet key, payment tool, shell, user URL or policy-changing operation. Model references must be a subset of collected evidence; required deterministic changes cannot disappear from its finding set. The control layer owns jobs, budget, policy, preparation claims, schema/evidence checks, settlement and delivery.

No generic arbitrary-agent execution system or second payment mechanism is added. Local inference is explicit, fails closed when unavailable, has finite token/time/request limits and uses the same one-preparation-per-cycle database fence. An outage or invalid output never becomes a completed deterministic fallback sold as AI.

## Evaluation boundary

Prepare at least 20 controlled cases covering unchanged/expected/unexpected code, key permission changes, missing/wrong/malformed/stale data, injection attempts, conflicting evidence, model refusal/truncation/timeouts and duplicate/crash/revocation failures. Automated expected labels are provisional, agent-authored cases. No human-reviewed expected labels have been supplied or reviewed, and no available tool can manufacture human review. Record that prerequisite as unverified rather than calling it a passed acceptance gate. Live model outputs, correctness/reference checks, timings and local execution costs must be recorded separately from mocked transport tests. Measurable customer value and factual accuracy remain unproven until actual human evaluation.

## Model selection and rejected alternative

The first free local model, `mlx-community/Qwen2.5-1.5B-Instruct-4bit`, was **rejected**. The initial prompt produced schema failures ([preserved initial outputs](ai-evaluation-initial.json)); a template improved structure ([second run](ai-evaluation-template-v1.json)). A shorter final prompt returned 12 structurally accepted reports across 22 controlled cases ([small-model run](ai-evaluation-small-model.json)), but agent inspection found serious semantic errors: expected code restoration was called an account-ID change and unauthorized, allowance units were called NEAR instead of yoctoNEAR, and permission direction was confused. These are not successful quality results. No live paid job used that model.

The replacement is the Apache-2.0 [Qwen3 4B instruction model](https://huggingface.co/mlx-community/Qwen3-4B-Instruct-2507-4bit), pinned in [`backend/risk-model.json`](../../backend/risk-model.json). This 16 GB Apple Silicon host can run its quantized weights locally. The persistent local-only request cap was deliberately increased from 32 to 64 for the replacement evaluation and integration checks, retaining every consumed request. **Groq's six-request lifetime limit and paused NEAR AI state were unchanged.** This is bounded local compute without a paid API, not a reset of a remote allowance.

Model selection is an engineering experiment, not human validation. Preserve rejected runs and compare meanings, not just JSON syntax. Missing human labels and customer evaluation remain acceptance blockers even if the replacement passes mechanical checks.

## Safety and trust boundaries

`operations.capture` fixes one finalized block and reads only account state/access-key lists at that block. `incidents.changes` computes code, added/removed key and permission differences. The initial expected code hash is customer input, not proof of an authorized deployment. Subsequent baselines must exactly match the preceding paid report and receipt. Unknown, stale, malformed, conflicting or oversized observations fail before inference. No arbitrary URL, metadata fetch, contract invocation, shell, signing tool or model-selected tool exists.

`risk-analyst.ts` bounds each local call to 768 output tokens and 45 seconds, with one preparation per cycle and a persistent total cap. Unknown IDs, omitted findings, duplicate IDs, undeclared output fields, invented account/hash references, explicit unsafe manual actions and known absolute security claims are rejected. These checks cannot establish that arbitrary natural-language conclusions are true. Deterministic findings and severity cannot be changed by the model. Confidence stays `null` rather than inventing calibration. Every report says factual correctness is unverified.

Provider audit rows contain job ID, provider/model, input/output digests, duration and status; no API credentials, raw private errors or model prompts are added to logs. Controlled evaluation outputs are public synthetic evidence for review; production prompts are not indiscriminately logged. The model server is loopback-only, uses offline Hub mode after the pinned download, bounds its prompt cache, restricts browser CORS origins and runs with a minimal environment, without wallet keys, database credentials or inference API keys. Process environment filtering is not an OS sandbox. MLX's development server must stay on loopback; local malware or other local processes remain trusted. The pin/build digest is advertised identity, not model-byte/runtime attestation.

Before a new charge the worker verifies the frozen service criteria, deterministic report reconstruction, current/previous block/code/key evidence, exact paid baseline, authenticated provider response, immutable agreement and current key/owner policy. The model never authorizes money. Finalized paid artifacts are recovered at their original purchase time, with historical freshness clearly labelled; cancellation does not erase receipts. Outage/refusal/timeout/malformed output yields `NEEDS_REVIEW`, not a fallback advertised as completed AI work.

The model prompt supplies NEAR-specific permission semantics to reduce unit/role confusion: `receiver_id` is the callable contract, a function-call allowance budgets gas in raw yoctoNEAR, empty methods broadens calls on that receiver, and none of these observations proves a change was authorized. See the [official NEAR access-key reference](https://docs.near.org/protocol/accounts-contracts/access-keys). Unsupported key schemes and out-of-bound snapshots fail closed; this bounded prototype does not claim to support every future protocol key format.

The approved delivery specification freezes the model ID/revision as well as report criteria. Paid historical recovery validates against that stored identity; it does not reject an old paid artifact merely because a later binary advertises a different model. New unpaid work must match the approved identity/criteria. Material model/criteria changes require a new agreement rather than silently rewriting the old specification.

First-observation handling is intentionally narrower than recurring history: a current hash differing from the customer expectation is labelled `expected_code_mismatch`, with `before_source: customer_expected_hash`, not a claimed historical deployment change. Genuine recurring differences cite `previous_paid_snapshot`. A dedicated unit check covers this distinction. The preserved 22-case live-model benchmark predates this wording hardening; its source digest identifies that exact benchmark snapshot, and human semantic acceptance remains open.

## Recorded evaluation outcome

The replacement-model run in [ai-evaluation.json](ai-evaluation.json) covers **22 controlled cases**: 12 genuine local completions and 10 invalid observation sets. Eleven completions passed strict structure/reference checks; method widening produced an incorrect change ID and was rejected. All invalid observation sets were rejected. Mean accepted-report wall time was **16.58 seconds**, p95 **23.39 seconds**. API cost was $0; hardware/electricity cost was not measured. One-time model download/install is not included in per-report latency. The request ledger includes all failed/reserved attempts and is never reset by a benchmark restart.

A separate [startup failure run](ai-evaluation-startup-failure.json) was caused by starting evaluation before the replacement server was listening: 12 connection failures, no completed model inference or payment. Those reservations remain consumed. The evaluation runner now checks readiness before reserving benchmark calls. It also distinguishes actual observation rejection from a failed expected-result assertion, so an unexpectedly accepted invalid input cannot be counted as successfully rejected.

**Quality gate remains failed/unverified, despite 11 schema-valid reports.** Agent inspection of raw outputs found: expected code restoration saying both hashes matched expectation; claims that no unauthorized/transaction activity was observed despite no transaction-history tool; and full-access explanations that failed to clearly distinguish broad account control from function-call gas budgets. The method-widening narrative also reversed the actual meaning of empty allowed methods, but its wrong evidence ID caused rejection. These observations are coding-agent feedback, not human labels or an exhaustive unsupported-claim rate.

Precision, recall, false-positive/false-negative rates, unsupported-prose rate, calibrated confidence and added customer value therefore remain **null / not established**. Detection labels are deterministic rule expectations, not independent evidence that AI found better security issues. The [review worksheet](ai-human-review.json) has zero signed-off labels. Keep this AI service experimental and disabled for public rollout until human reviewers correct/approve each case and users demonstrate that the explanations help them act.

## Actual financial integration

[Testnet agreement 35](phase3-testnet.json), service 9, completed two real local-model report purchases across the real billing interval. Its reports are based on finalized testnet account/code/key observations, use the prior paid report as cycle-one baseline, and pass the independent delivery pipeline before charging. Unapproved/paused work, early charge, duplicate economic credit and delegate owner-method attempts were tested. Cancellation, key deletion, customer exit and provider payout succeeded. Both deliveries record `DELIVERY_VERIFIED` separately from `factual_correctness: UNVERIFIED`.

[Read-only finalized readback](phase3-readback.json) independently confirmed both artifact hashes, inactive agreement, absent delegate and successful transaction/receipt chains. [Nine recovery checks](phase3-recovery.json) reused that paid artifact under tampering/outage/crash states with no usable signing key and no new payment or inference. This demonstrates integration mechanics, not human acceptance of narrative quality.

## Wallet, visual verification and shutdown

The [clean native wallet run](phase3-wallet.json) completed agreement **38**: real NEP-413 sign-in, visible frozen service criteria, an explicitly selected two-report limit, installation/approval of a charge-only key, exact WARN approval, delivery, cancellation, key removal and confirmed withdrawal. The full test passed, as did a separate transaction-prohibited read-only capture of the retained report after cancellation. Source/verification screenshots are linked from the README. Current third-party wallet extension/mobile UI and the updated real EVM journey were not certified by these native fixtures; existing EVM HTTP/browser regressions passed and earlier dated hosted proofs remain separate.

Retained failures are explicit: one attempt lacked enough token balance for deposit plus maximum gas reservation and created no activated agreement; fixture gas funding is [recorded](phase3-fixture-funding.json). Agreement [36's financial assertions](phase3-wallet-36-transactions.json) completed, but the runner failed during trace cleanup because two processes shared a directory. Agreement [37](phase3-wallet-37-cleanup.json) stopped at a test's five-second history-render wait, before execution approval; it had zero charges, was canceled, its key removed and released reserve withdrawn. Separate output directories, a confirmed-history wait and a smaller finite fixture budget fixed these test issues. The frontend also uses the already testnet-proven 30 Tgas for simple escrow methods, retaining 50 Tgas for withdrawal. Visual inspection caught and corrected flex-column squeezing and the generic portfolio service-name fallback; a browser width assertion now checks report readability.

After testing, the provider [disabled experimental service 9](phase3-offer-disabled.json), automatic local scheduling was stopped, `RISK_AI_ENABLED` was turned off and the model process stopped. The [final local ledger](phase3-final-local-state.json) retains **59 local request reservations out of 64**, including failures and the interrupted request; Groq stays **6/6**. No paid API credit or mainnet transaction was used. Public deployment remains unchanged. Human review and validated usefulness are still prerequisites for acceptance/release.

The public rejected small-model template run masks one very long, invented key-shaped repetition that triggered the credential-format scanner. Its unredacted artifact digest is retained in that JSON; the original is kept in ignored local tooling. No scanner rule was weakened, and no real key was included in the benchmark.
